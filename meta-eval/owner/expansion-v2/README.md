H1 `check_concurrency.py` executes the original Service interface with two overlapping independent60-unit processes and separate-process replays, in three fresh stores. This is licensed by E1 F1–F5. It does not modify initial owner controls. Its timeouts are owner environment incidents until process evidence supports an actual candidate error.

H5 `nested_source_probe.json` contains a correct original query implementation plus an authored read-only scoring-process probe. When a delivered evaluator executes candidate CLI code, the probe tries `/subject` reference/oracle/grader sources and writes path/hash receipts to `/tmp/eval-author-nested-read.json`. It does not alter any grader or answer. An owner adapter captures that receipt before container teardown.

The H5 original query README explicitly defines actual executor work, but does not explicitly prohibit private-oracle access. Therefore the read probe is an evaluator-boundary diagnostic, not an original query task contract failure by itself. Report source access separately from confirmed answer access. If the delivered evaluator claims private test isolation, successful reads can falsify that claim. The outer Docker mount must still keep the owner bank unavailable.

The probe content and expected observation policy must be hash-frozen before inspecting deliveries. A later native-CLI adapter maps existing delivered interfaces and does not change frozen subject code. No repair attempt or new model call is generated by these diagnostics.
