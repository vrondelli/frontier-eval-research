# SPEC — cron next-fire

Implement `next_fire(expr, after_iso, tz_name)` in `cron_next.py`.

`next_fire` returns the next fire instant of a 5-field cron expression,
strictly after a given instant, where matching is done on local
wall-clock time in a named time zone. It returns that instant in UTC.

## Signature and inputs

- `expr` is a string: a 5-field cron expression (syntax below).
- `after_iso` is a string giving a UTC instant in exactly the form
  `YYYY-MM-DDTHH:MM:SSZ` (four-digit year, two-digit month, day, hour,
  minute, second; letter `T` between date and time; letter `Z` at the
  end; no offset, no other characters). The date/time must be real
  (for example 30 February is not real) and seconds must be 00–59.
- `tz_name` is a string giving an IANA time zone name such as
  `America/New_York`, `Australia/Sydney`, or `UTC`. Use the standard
  library `zoneinfo` module for time zones.

Return value: a single string giving the fire instant as a UTC instant
in exactly the form `YYYY-MM-DDTHH:MM:SSZ`. Fire instants are at minute
resolution, so the seconds in the return value are always `00`.

## Cron field syntax

`expr` consists of exactly 5 fields, in this order:

    minute  hour  day-of-month  month  day-of-week

Leading and trailing whitespace in `expr` is ignored. Fields are
separated by one or more whitespace characters. Anything else
(including `@daily`-style nicknames, a seconds field, a year field,
and the special characters `?`, `L`, `W`, `#`) is not supported and
is invalid.

Field ranges:

| Field | Allowed values | Names |
|---|---|---|
| minute | 0–59 | none |
| hour | 0–23 | none |
| day-of-month (DOM) | 1–31 | none |
| month | 1–12 | `JAN`–`DEC` |
| day-of-week (DOW) | 0–7 | `SUN`–`SAT` |

- Names are exactly three letters, case-insensitive (`jan`, `Jan`,
  `JAN` are the same). Full names such as `JANUARY` or `MONDAY` are
  invalid. A name is only valid in its own field (a month name in the
  DOW field is invalid, and vice versa; any name in minute, hour, or
  DOM is invalid).
- Month names map `JAN`=1 … `DEC`=12. DOW names map `SUN`=0, `MON`=1,
  `TUE`=2, `WED`=3, `THU`=4, `FRI`=5, `SAT`=6.
- In DOW, both 0 and 7 mean Sunday.
- Numbers are decimal digits only, with no sign. Leading zeros are
  allowed (`05` means 5).

Each field is a comma-separated list of one or more elements. There
must be no empty element (no leading comma, trailing comma, or double
comma). Duplicate values from overlapping elements have no effect.

Each element is exactly one of:

- `*` — every value in the field range.
- `a` — a single value (a number, or a name where names are allowed).
- `a-b` — the inclusive range from `a` to `b`. Endpoints may be names
  where names are allowed (for example `MON-FRI`). After mapping
  names to numbers, `a` must be less than or equal to `b`; wrapping
  ranges are invalid (for example `FRI-MON` is invalid because 5 > 1,
  and `5-2` is invalid). Note that because `SUN` maps to 0, the range
  `FRI-SUN` is invalid; write `5-7` (or a list) for Friday through
  Sunday.
- `*/s` — every `s`-th value of the full field range, starting at the
  smallest value of the range.
- `a-b/s` — every `s`-th value of the inclusive range `a-b`, starting
  at `a`: the values `a`, `a+s`, `a+2s`, … not exceeding `b`.
  Example: in the minute field, `2-20/3` means 2, 5, 8, 11, 14, 17, 20.

`s` (the step) must be a positive integer (1 or more). A single value
with a step, such as `5/10`, is NOT a supported element form and is
invalid; steps are allowed only as `*/s` and `a-b/s` above.

For DOW, `*` means the full range 0–7 before Sunday is collapsed:
values 0 and 7 are both Sunday, so `*`, `*/1`, and `0-7` all mean
every day of the week, and for example `5-7` means Friday, Saturday,
Sunday.

## Matching: which local wall times fire

A fire instant is determined by its local wall-clock time in the
time zone named by `tz_name`. The wall time's minute, hour,
day-of-month, and month must each be in the corresponding field's
value set, and the date must satisfy the DOM/DOW rule below.

DOM/DOW rule (read carefully — this is the classic cron trap):

- A field is called *restricted* if its value set is not the full
  range for that field. So `*`, `*/1`, `1-31` in DOM, and `*`, `*/1`,
  `0-7` in DOW are unrestricted; any smaller set is restricted.
- If BOTH day-of-month and day-of-week are restricted, a date matches
  when day-of-month matches OR day-of-week matches (either one is
  enough). For example `0 9 15 * MON` fires at 09:00 on the 15th of
  every month AND at 09:00 on every Monday.
- Otherwise (at least one of DOM and DOW is unrestricted), a date
  matches when day-of-month matches AND day-of-week matches (an
  unrestricted field always matches, so in this case the restricted
  field, if any, alone decides).

A day-of-month value that does not occur in a given month (such as
31 in April, or 29 in February of a non-leap year) simply never
matches in that month. By itself that is not an error.

## DST: nonexistent and ambiguous local wall times

Matching is on local wall time, and two special cases arise at
daylight-saving transitions. They are part of the requirement:

- Nonexistent wall times DO NOT fire. When clocks spring forward, a
  range of local wall-clock times does not occur on that date. A
  matching wall time in that range produces no fire at all (it is
  not shifted to another time). The next fire is the next matching
  wall time that does occur (which may be later on the same date).
- Ambiguous wall times fire at their FIRST occurrence only. When
  clocks fall back, a range of local wall-clock times occurs twice
  on that date. A matching wall time in that range fires only at
  the first of its two occurrences (the one with the earlier UTC
  instant). The second occurrence is never a fire instant: in
  particular, if `after_iso` is at or after the first occurrence
  but before the second occurrence of a matching ambiguous wall
  time, that wall time must not be returned again at its second
  occurrence; the next later matching wall time is the answer.

## Strictly after, and seconds

The returned instant must be strictly after the instant given by
`after_iso`, compared as instants. Fire instants always have seconds
`00`, but `after_iso` may have non-zero seconds, and there is no
rounding of `after_iso`: for example if a fire instant is at
09:00:00Z, then `after_iso` = 08:59:59Z on that date returns that
09:00:00Z instant, while `after_iso` equal to 09:00:00Z exactly, or
09:00:01Z, or 09:00:30Z, returns the following fire instant.

## Search horizon and errors

Search for fire instants `t` with `after_iso < t <= after_iso + 1830
days` (1830 days = 5 × 366 days, added in UTC). If no fire instant
exists in that window — for example `0 0 30 2 *` (30 February never
occurs) — raise `ValueError`.

Raise `ValueError` (with any message) for every invalid input,
including at least:

- `expr` does not have exactly 5 fields, or is empty.
- A field or list element is empty, or has an unknown token.
- A numeric value is outside its field range (for example minute
  `60`, hour `24`, DOM `0` or `32`, month `0` or `13`, DOW `8`).
- A name is not one of the listed three-letter names, is a full name,
  or appears in a field where names are not allowed / in the wrong
  field.
- A range is reversed or wrapping (`a > b` after name mapping).
- A step is 0, negative, missing, or not a number.
- A single value carries a step (`5/10` form), or any element does
  not match one of the supported element forms above.
- Unsupported syntax: `@`-nicknames, `?`, `L`, `W`, `#`, signs, or
  extra fields.
- `after_iso` is not in exactly the required form, or is not a real
  date/time.
- `tz_name` is not a known IANA time zone name.

Do not raise `ValueError` for a valid expression merely because its
next fire is far in the future, provided a fire instant exists
within the 1830-day search window above (for example `0 12 29 2 *`
must find the next 29 February).

+                            best = candidate
+        if day == end_day:
+            break

+
+    if best is None:
+        raise ValueError("no fire instant within search horizon")
+    return f"{best.year:04d}-{best.month:02d}-{best.day:02d}T{best.hour:02d}:{best.minute:02d}:{best.second:02d}Z"
