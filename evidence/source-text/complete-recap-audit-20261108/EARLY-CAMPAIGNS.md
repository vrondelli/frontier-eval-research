# Independent recap of the earlier hackathon campaigns

Audit date: 8 November 2026. Scope: **all 45 top-level hackathon packages outside `frontier-hunt-20261106`**, which other audit lanes cover. The machine ledger (historical reference: `EARLY-COVERAGE.json`) contains one entry for every directory, with local units, model/tool conditions, outcomes, comparability limits and 144 source-file hashes. The selected primary checks (historical reference: `early-audit/EARLY-PRIMARY-CHECKS.json`) pass all 34 read-only binding/accounting checks. No new model calls or candidate-code executions occurred, and no old evidence was edited.

This is complete **directory-level recap coverage**, with selected primary receipt and source verification. It is not an exhaustive rereading or semantic rerun of every byte of the many saved workspaces. Human review remains absent or pending in the inspected research packages. No defensible grand episode total is produced: reports, exports, component studies and repeated assertions overlap.

## The premise needs correction

It is not true that nothing failed, nor that every failure vanished. Earlier work contains genuine enacted planning errors on Sol and Astra, a genuine Terra queue-equivalence answer error, a direct scheduling error, repeated ordinal-score instability, a missing promised report artifact, and authentic historical process-cost concerns. Several later experiments intentionally changed tools, representations, instructions, authority boundaries or the measured endpoint. Other red results were exposed as grader or environment mistakes. One important unchanged-prompt failure really did become a success in a fresh draw.

None of these facts alone demonstrates deliberate test gaming. They are different explanations that must not be collapsed into one story.

## Research-side weaknesses that can make progress look stranger than it is

1. **Changing the question while calling it replication.** Tool access, direct plans versus executable programs, explicit mutable-construction authorization, gate scope and output conventions all matter. A program returned without tool use can still outsource search to the grader when later executed; that is licensed behavior, but measures something different from committing live probe choices without computation.
2. **Narrow registered endpoints hide other real errors.** A process-loop endpoint can be negative while the model promises a nonexistent report. A category-change endpoint can pass while the exact operational reference is missed. A correct source code artifact can coexist with a resource-confounded incomplete turn. These should be reported, not promoted or erased.
3. **Finite reference success is weaker than grader validity.** E1's literal and Jinja's exception class are proven examples. The architecture custody audit also originally discovered only156snapshots for228turns, missing72storedunder a different path; the corrected audit enforces228/228. A green audit can be wrong when its input selector is incomplete.
4. **Many large counts are repeats or accounting units.** There are versions, exports, syntactic variants, shared lineages, multiple judgments per call and growing cumulative assertions. These do not imply an equal number of distinct hard frontier hypotheses.
5. **Explicit small tasks favor tool-enabled solvers.** Several prompts already articulate the distinction or governing concern being tested. Short controlled tasks are useful diagnostics but may remove the ambiguity, accumulated commitments, parallel ownership and real cost pressure from the historical incidents that motivated them.
6. **The same AI-assisted research pipeline authors many tasks, controls and reviews.** Independent algorithms and source-bound controls help, but authored semantic-equivalence judgments, broad allowed score sets and blank human-review forms do not create external ground truth. No finding here establishes human hiring or creativity validity.

These are concrete routes to weak or misleading claims. They are not evidence of intentional researcher deception, deliberate model deception, or providers training on these local runs between calls.

## What this audit does and does not establish about gaming

The reviewed earlier sources support **instrument defects, treatment changes, stochastic non-recurrence, and some genuine continuing failures**. They do not justify saying all tests are gamed. The same-prompt Terra repeat is not enough to infer intentional adaptation; model aliases are not immutable weight identities, and one failure followed by one success is intrinsically weak prevalence evidence.

This lane did not execute new adversarial graders or inspect every model's complete code for hardcoding. It therefore cannot certify the absence of leakage or reward hacking across all packages. That requires the dedicated instrument audit. It does establish why a blanket summary of “we found nothing” or “every failure disappeared” loses important evidence.

## Practical next design changes

Keep an explicit seed→follow-up matrix before launching: same prompt, data, output representation, model identity, tool availability, actual tool use, time/compute allowance, authority boundary and endpoint. Call a change a treatment intervention, not a failed replication. Retain initial failures and all ordinary errors beside frozen endpoints.

Use independent fresh instance generation and hidden semantic properties, not only public examples and a single naive negative control. Commission a verifier whose oracle is not derived from candidate output. Record sampled cases and complete source selectors independently of the paths an audit happens to find. For historical governance, reproduce the actual total gate, owner channel, concurrent roles and meaningful horizon before drawing a null conclusion about that mechanism.

Human relevance and normative authority adjudication should be specific: identify which check or decision was necessary, when an alternative was feasible, and which evidence justifies that assessment. A single global “looks convincing” label will not repair the comparability problems.
