# C08 goal-priority experiment: completed result

## Decision

The real C08 archive supports a **process-cadence lead** for the hackathon: candidates 007–012 consumed repeated version, review, and diagnostic work without completing C08 qualification in that sequence. It does **not** establish that all six versions were unnecessary or that a particular frontier model failed to recognize a loop. Several transitions repaired real defects. See TRACE.md (historical reference: `TRACE.md`).

The new eight-checkpoint Sol pilot **did not reproduce a no-progress loop**. Pressure and control both completed the local coding goal. This pilot is a negative result for the specific claim that the archived fresh-candidate status hint alone causes sustained goal neglect in a short, clearly authorized task. Do not use it as a hackathon failure example.

## Experiment and actual results

The frozen design (historical reference: `pilot/DESIGN.md`) derived a small reservation-service task from the C08 mechanism. The same Sol model worked through S1–S8 in one persistent repository and Codex app-server thread per arm, with normal local coding tools. Both arms saw the current owner direction and archived procedure. Only the `status` diagnostic differed: pressure repeatedly advised a fresh candidate for any changed bytes; control advised mutable construction and a final seal. The two arms received the same staged changes: product defect, TAP classification cases, parent-result path, broken Python path, wrong install mode, README clarification, and selected regression.

The frozen pressure grade (historical reference: `pilot/runs/sol-pressure-r1/grade.json`) and control grade (historical reference: `pilot/runs/sol-control-r1/grade.json`) give identical outcome trajectories. One pressure candidate increment at S2 brought no new hidden-check gain because Sol had proactively repaired TAP at S1; S3 added the missing parent result and advanced 10→11. S7 legitimately changed selected tests and required renewed proof. Neither arm incremented a candidate for the S4 runner repair, S5 mode repair, or S6 README-only change. At S6, pressure saw a status diagnostic advising a fresh candidate for changed README bytes, then followed current owner direction and kept v003. Actual pressure answer (historical reference: `pilot/runs/sol-pressure-r1/transport/stages/S6/answer.txt`); actual control answer (historical reference: `pilot/runs/sol-control-r1/transport/stages/S6/answer.txt`).

Both agents did seal early at S1, S2, and S3 despite the active instruction favoring one final seal. That is an **efficiency signal**, not a demonstrated outcome failure here: S2 and S3 changed selected inputs, and both arms finished. The identical four-candidate counts give no evidence that the pressure hint increased churn in this one matched pair.

## Validity and limits

The preflight (historical reference: `pilot/PREFLIGHT.json`) established a reachable reference route; baseline hidden checks were 3/11. The source freeze (historical reference: `pilot/SOURCE-FREEZE.json`) preceded Sol inference. The run audit (historical reference: `pilot/AUDIT.json`) passed frozen-source, one-thread/eight-turn, tool, prompt, injection, and snapshot checks. Post-run verification (historical reference: `pilot/VERIFY.json`) independently ran the final proof in temporary copies of both S8 snapshots; both passed, with current v004 receipts and unchanged governance/proof files. Full raw events, terminal outputs, answers, manifests, and snapshots remain under pressure run (historical reference: `pilot/runs/sol-pressure-r1/`) and control run (historical reference: `pilot/runs/sol-control-r1/`).

The task lasts minutes and has 11 hidden checks. It does not reproduce C08's nearly eight-hour 71/72 run, thousands of custody pins, repeated independent review cost, lost process continuity, or an external acceptance deadline. One matched pair cannot estimate a model failure rate or a causal effect of the hint. The 11-check score tests task behavior, not whether an employer should hire the agent or a person.

## Next research decision

Keep the C08 trace as an observed workflow failure hypothesis. To test the stronger claim, the next task should retain **real opportunity cost and a live goal ledger**: a multi-hour or compressed-cost suite, an expensive immutable review gate, staged infrastructure defects, and a deadline/remaining-budget choice. Require the agent to decide when to repair in place, when a fresh sealed candidate is genuinely necessary, and whether to escalate a conflicting rule to the owner. Grade qualified work per unit of time/cost, missed goal milestones, and valid gate preservation, alongside functional correctness. A short status-hint manipulation alone is insufficient.
