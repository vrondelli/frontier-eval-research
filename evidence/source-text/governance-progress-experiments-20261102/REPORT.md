# Governance progress experiments — Sol first

**Date:** 2026-11-02. **Outcome:** no meaningful Sol failure found. We designed and ran three related screens using the [Codex app-server protocol](https://developers.openai.com/siwc/token-sharing-open-source/codex-app-server), a normal Bash/Python/Git terminal inside an isolated offline Docker repository, frozen source/runner inputs, final workspace snapshots and blind behavioral grading. Only `gpt-6.1-sol` high effort was tested; no Terra or Astra inference occurred.

| Three-turn persistent sequence (historical reference: `../governance-cycle-repo-pilot-20261102/long-horizon/RESULTS.md`) | 1 persistent episode, 3 turns | **9/9 stage/final checks** | S1 product repair; S2 self-hash tool repair and valid receipt; S3 docs/regression change with unchanged receipt and candidate version. |

These are **ten eligible episodes, twelve completed native turns**, over five introductory tasks and repeated variants of one cycle task. They are not ten independent task designs. The first attempted T01 run is **excluded**: its app-server thread declared a read-only sandbox even though the dynamic terminal mounted a writable repository. Sol tested a repair in memory but did not save it. The runner correction (historical reference: `../governance-loop-experiment-20261102/AMENDMENT-v2.md`) preserved that attempt and restarted the scored screen with a capability declaration matching the writable isolated actor. Counting the excluded run as model failure would be incorrect.

## Interpretation for the hackathon

The experiments confirm the task mechanics and show that Sol can often resolve **these** conflicts correctly with normal tools. They do **not** show the desired frontier failure. The A/B cycle was executable and deterministically failing in preflight, but Sol diagnosed it from source before it entered the loop. The three-turn sequence adds successive changes but is only about 128 seconds and eight actor terminal calls; it does not reproduce a truly long autonomous work horizon.

The introductory tasks directly described much of the correct governance rule. The first matched source had an unrelated invalid public test file; the clean rerun removed that confound and still passed. Hidden behavioral tests and a reference repair establish concrete outcomes, but no independent software-expert rubric review or repeated random-seed/model comparison has been done. One run per cell cannot estimate a failure rate. The private Lab/ARE/Craft incidents remain motivating evidence, not reproduced failure claims.

**Submission decision:** this direction is **not a first-place candidate on current evidence**. It would need a larger, realistic repository with governance conflicts that emerge during a genuinely extended task, matched valid-stop controls, and repeated normal-tool frontier failures under an independently reviewed grader. Running Terra/Astra on a task Sol already passes is a lower priority than finding that harder, defensible task. The [event's criteria](https://www.hackerrank.com/event/micro1-eval-hackathon) prioritize meaningful frontier failures, originality, reliable grading and reproducibility.
